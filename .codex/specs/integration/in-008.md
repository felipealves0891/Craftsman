# Estudo IN-008: Integracao com Correios

Resumo tecnico: a integracao com Correios e viavel, mas o primeiro escopo recomendado para o Craftsman deve ser rastreio, nao calculo de frete nem postagem completa. O modelo atual ja possui `Shipment`, `ShipmentStatus`, `IShippingTracker` e `TrackedShipmentStatus`, o que permite acompanhar objetos postados sem expandir o dominio agora.

Calculo de frete, prazo, pre-postagem e etiquetas devem ficar para evolucao posterior, porque dependem de contrato, cartao de postagem, permissoes no CWS, credenciais, dados de remetente/destinatario, embalagem, declaracao de conteudo ou NF-e, servico contratado e validacoes operacionais ainda fora do modelo interno.

## Viabilidade

- Recomendacao inicial: integracao ativa de rastreio, implementada futuramente atras de `IShippingTracker`.
- Possivel evolucao: calculo de preco/prazo quando houver contrato ativo, cartao de postagem e servicos habilitados.
- Possivel evolucao posterior: pre-postagem, etiquetas e postagem operacional via PPN/API, depois de modelar dados de pacote, remetente, destinatario, documentos fiscais/declaracao e regras de servico.
- Nao recomendado agora: implementar postagem completa no primeiro passo, porque isso acoplaria a integracao a decisoes comerciais e dados que o Craftsman ainda nao representa.

## Modelo Interno Atual

O Shipping Context hoje representa envio com:

- `Shipment.TrackingCode`: codigo de rastreio.
- `ShipmentStatus.Created`: envio criado internamente.
- `ShipmentStatus.InTransit`: objeto postado ou em transporte.
- `ShipmentStatus.DeliveryAttempted`: tentativa, ausencia, aguardando retirada ou pendencia de entrega.
- `ShipmentStatus.Delivered`: entrega concluida.
- `ShipmentStatus.Cancelled`: envio encerrado/cancelado por decisao interna.
- `IShippingTracker.TrackAsync`: contrato para consultar status externo por codigo de rastreio.
- `TrackedShipmentStatus`: retorno minimo com `TrackingCode`, `Status` e `TrackedAt`.

O modelo atual nao guarda historico de eventos de rastreio, localidade, unidade operacional, municipio, UF, descricao externa, previsao de entrega, valor de frete, dimensoes, etiqueta ou dados completos de postagem.

## Autenticacao, Contrato e Credenciais

As APIs dos Correios usam token REST gerado a partir de credenciais do Meu Correios, podendo variar conforme o tipo de autorizacao:

- autenticacao por login/senha do Meu Correios;
- autenticacao associada a contrato comercial;
- autenticacao por cartao de postagem;
- uso de CWS para gestao de acesso, APIs autorizadas e subdelegacao.

Pontos relevantes:

- APIs restritas dependem de contrato ativo e permissao especifica.
- API Preco exige cliente com contrato e servico `38202 API PRECOS` vinculado ao contrato/cartao.
- API Prazo exige cliente com contrato e servico `38210 API PRAZOS` vinculado ao contrato/cartao.
- O CWS permite subdelegacao de acesso a terceiros, mas chaves de subdelegacao podem expirar em ate 180 dias e precisam ser recriadas.
- Credenciais, token, contrato, cartao de postagem e chaves nao devem ficar expostos em codigo ou logs.

## APIs e Canais Oficiais

- API Token: gera tokens para acesso as APIs, com variacoes por login, contrato ou cartao de postagem.
- API Preco: calcula valores de frete, mas e restrita a clientes com contrato e servico habilitado.
- API Prazo: calcula prazos, mas tambem e restrita a clientes com contrato e servico habilitado.
- API Rastro: canal tecnicamente mais aderente ao `IShippingTracker`, mas a consulta passou a ser restrita a objetos vinculados ao contrato do remetente.
- Correios Web Service (CWS): canal para credenciais, autorizacoes, APIs permitidas e subdelegacao.
- PPN/Pre-Postagem: canal operacional para pre-postagem, rotulos/etiquetas, cartoes de postagem, remetentes, destinatarios e embalagens.

## Mapeamento Para o Craftsman

Mapeamento minimo recomendado para rastreio:

- codigo do objeto Correios -> `Shipment.TrackingCode`.
- status/evento externo atual -> `TrackedShipmentStatus.Status`.
- data/hora do evento externo -> `TrackedShipmentStatus.TrackedAt`.

Mapeamento de eventos Correios para `ShipmentStatus`:

- objeto criado, pre-postado ou aguardando postagem -> `Created`.
- postado, encaminhado, em transito ou saiu para entrega -> `InTransit`.
- tentativa nao efetuada, destinatario ausente, aguardando retirada ou pendencia operacional de entrega -> `DeliveryAttempted`.
- entregue -> `Delivered`.
- cancelado, devolvido sem entrega, objeto nao utilizavel, extraviado ou ocorrencias definitivas semelhantes -> nao converter automaticamente para `Cancelled`; registrar como ocorrencia externa em uma evolucao futura e exigir decisao operacional interna para encerrar o envio.

Dados relevantes fora do modelo atual, mas recomendados para evolucao:

- historico completo de eventos;
- codigo e descricao do evento externo;
- unidade, localidade, municipio e UF;
- previsao de entrega;
- servico Correios utilizado;
- contrato e cartao de postagem associados;
- dados de auditoria da consulta.

## Dados Para Evolucoes Futuras

Calculo de frete e prazo exigiria modelar ou obter:

- CEP de origem e destino;
- servico Correios;
- peso;
- dimensoes;
- adicionais;
- contrato/cartao quando aplicavel;
- regras de elegibilidade do servico.

Pre-postagem e etiqueta exigiriam modelar ou obter:

- contrato, cartao de postagem e permissao no CWS/PPN;
- remetente;
- destinatario;
- embalagem;
- declaracao de conteudo ou NF-e;
- servico e adicionais;
- formato e impressao de rotulo;
- validacoes operacionais dos Correios.

## Riscos e Lacunas

- A disponibilidade das APIs varia conforme login, contrato, cartao de postagem e permissoes no CWS.
- Rastro foi reforcado com restricao para objetos vinculados ao contrato do remetente, o que limita consultas genericas.
- Chaves de subdelegacao no CWS podem expirar em ate 180 dias e nao devem ser tratadas como segredo permanente.
- Pre-postagem e etiquetas dependem de cadastro operacional de remetentes, destinatarios, embalagens, cartoes e documentos.
- Validacoes de pre-postagem podem mudar por regra operacional dos Correios, como obrigatoriedade de declaracao de conteudo e validacao de NF-e.
- O Craftsman ainda nao possui historico de rastreamento, campos de pacote, cotacao, etiqueta, documentos fiscais ou dados completos de postagem.
- Converter eventos negativos externos diretamente para `Cancelled` pode encerrar indevidamente um envio; a decisao deve continuar no fluxo interno.

## Conclusao

A IN-008 deve registrar Correios como integracao viavel com primeiro escopo de rastreio. A futura implementacao deve consultar a API Rastro por meio de um adaptador de infraestrutura que implemente `IShippingTracker`, mantendo o dominio desacoplado das APIs externas.

Frete, prazo, pre-postagem e etiquetas devem ser tratados como fases posteriores, depois que houver contrato/cartao validos e depois que o modelo do Craftsman representar os dados operacionais necessarios.

## Detalhes da Implementacao

A integracao inicial foi implementada como rastreio via `IShippingTracker`, sem mudar o modelo de dominio e sem adicionar frete, prazo, pre-postagem, etiqueta ou historico de eventos.

Foram adicionados componentes de infraestrutura em `src/Infra/Integrations/Correios`:

- `CorreiosOptions`: configuracao `Correios`, desabilitada por padrao.
- `CorreiosTokenService`: gera token com Basic Auth e suporta token por login, contrato ou cartao de postagem.
- `CorreiosTrackingClient`: consulta o endpoint configuravel de rastreio e extrai o evento mais recente.
- `CorreiosTrackingStatusMapper`: converte descricao/codigo/tipo externo para `ShipmentStatus`.
- `CorreiosShippingTracker`: implementa `IShippingTracker` e retorna `TrackedShipmentStatus`.

Configuracao padrao:

- `Correios:Enabled = false`.
- Producao: `https://api.correios.com.br`.
- Desenvolvimento: `https://apihom.correios.com.br`.
- `TrackingPathTemplate = /sro-rastro/v1/objetos/{trackingCode}?resultado=T`.

O registro no DI preserva `StaticShippingTracker` quando `Correios:Enabled = false` e troca para `CorreiosShippingTracker` somente quando a integracao e habilitada.

Testes adicionados:

- mapeamento de descricoes de rastreio para `ShipmentStatus`;
- consulta HTTP de rastreio com bearer token;
- geracao de token com Basic Auth e contrato.
