# Plano IN-007: Implementar Importação de Pedidos Shopee

## Resumo

Implementar a integração Shopee como uma nova IOrderSource, mantendo o fluxo atual Importar -> Normalizar -> Produção. O primeiro escopo será
somente importação ativa de pedidos por polling/manual trigger, usando get_order_list + get_order_detail, sem webhooks, pagamento, logística ou
mudanças no modelo interno RawOrder.

## Passo a Passo

1. Atualizar .codex/tasks/integration/tasks.md com uma nova tarefa de implementação baseada na IN-007, com critérios de aceitação claros.
2. Criar configuração ShopeeOptions com Enabled, Environment, BaseUrl, PartnerId, PartnerKey, janela de busca e status permitidos; validar no
    startup via Options Pattern.
3. Criar persistência para lojas Shopee autorizadas: shop_id, access_token, refresh_token, expiração, status de autorização e timestamps.
    Proteger tokens com ASP.NET Core Data Protection.
4. Implementar assinatura HMAC-SHA256 em um serviço isolado, sem lógica de negócio, cobrindo chamadas com e sem access_token/shop_id.
5. Implementar cliente HTTP Shopee com IHttpClientFactory, System.Text.Json, timeouts, logs sem segredos e tratamento explícito de erro de
    autenticação, rate limit/transiente e resposta inválida.
6. Implementar fluxo de token: trocar code + shop_id por tokens e renovar access_token antes da expiração. Falha de refresh deve marcar a loja
    como “reautorização necessária”.
7. Implementar ShopeeOrderSource : IOrderSource: buscar pedidos por período/status, paginar, obter detalhes por order_sn e retornar RawOrder.
8. Mapear dados:
    - RawOrder.Source: "Shopee"
    - ExternalOrderId: order_sn
    - CustomerName: comprador ou destinatário disponível
    - CustomerEmail: null
    - ExternalItemId: model_id quando existir, senão item_id
    - Description: item_name + model_name quando houver variação
    - Quantity: quantidade do item
    - UnitPrice: preço pago/descontado disponível no detalhe
9. Registrar a fonte no DI apenas quando Shopee:Enabled = true, mantendo InMemoryOrderSource para desenvolvimento se já estiver habilitada.
10. Reusar o botão atual de importação em OrdersController.Import; não criar UI complexa para Shopee nesta etapa. Callback/autorização pode ser
    endpoint administrativo mínimo se necessário para salvar tokens reais.
11. Criar migração EF Core para a tabela de tokens/lojas Shopee e atualizar o snapshot.
12. Rodar dotnet build Craftsman.slnx e dotnet test Craftsman.slnx com DOTNET_CLI_HOME=D:\Source\Repos\Dotnet\Craftsman\.dotnet-home\.dotnet.
13. Após concluir a implementação e testes, marcar a nova tarefa como concluída em .codex/tasks/integration/tasks.md.

## Interfaces e Tipos

- Não alterar RawOrder, RawOrderItem, IOrderSource, OrderNormalizer ou OrderImportPipeline.
- Adicionar tipos de infraestrutura para Shopee: options, DTOs de request/response, signer, token repository/service, HTTP client e
ShopeeOrderSource.
- Adicionar entidade de persistência para loja/tokens Shopee, mantendo tokens fora de appsettings.
## Testes
- Unitários para mapeamento Shopee detail -> RawOrder, incluindo item com variação e item sem variação.
- Unitários para renovação de token antes da expiração e falha marcando reautorização.
- Teste de ShopeeOrderSource com HttpMessageHandler fake cobrindo paginação, detalhe por order_sn e erro parcial.
- Teste do pipeline garantindo deduplicação por Source = "Shopee" + ExternalOrderId.
- Integração EF InMemory para salvar/carregar loja Shopee e tokens protegidos.
- Build e test suite completa da solução.

## Critérios de Aceitação

- Pedidos Shopee válidos são importados pelo pipeline existente sem if/else por origem.
- O mesmo order_sn não é importado duas vezes.
- Tokens são armazenados por shop_id e não ficam em texto puro.
- Access token expirado é renovado antes da chamada de pedidos; refresh inválido exige reautorização.
- Falhas da Shopee são registradas em OrderImportResult.Failures sem bloquear outras origens.
- O domínio de vendas, produção, estoque, financeiro e envio não conhece DTOs ou regras da API Shopee.

## Detalhes da Implementacao

### Escopo implementado

A integracao Shopee foi adicionada como uma nova implementacao de `IOrderSource`, mantendo o fluxo existente `Importar -> Normalizar -> Producao`.
Nao foram alterados `RawOrder`, `RawOrderItem`, `IOrderSource`, `OrderNormalizer` ou `OrderImportPipeline`.

A fonte Shopee fica isolada em `src/Infra/Integrations/Shopee` e retorna pedidos normalizados no contrato bruto interno:

- `RawOrder.Source`: `Shopee`
- `RawOrder.ExternalOrderId`: `order_sn`
- `RawOrder.CustomerName`: `buyer_username` quando disponivel, senao nome do destinatario
- `RawOrder.CustomerEmail`: `null`
- `RawOrderItem.ExternalItemId`: `model_id` quando existir, senao `item_id`
- `RawOrderItem.Description`: `item_name` com `model_name` quando houver variacao
- `RawOrderItem.Quantity`: `model_quantity_purchased`
- `RawOrderItem.UnitPrice`: `model_discounted_price` quando positivo, senao `model_original_price`

### Configuracao

Foi criado `ShopeeOptions`, carregado da secao `Shopee` em `appsettings.json` e `appsettings.Development.json`.
A integracao fica desabilitada por padrao:

- `Enabled`
- `Environment`
- `BaseUrl`
- `PartnerId`
- `PartnerKey`
- `SearchWindowHours`
- `RequestTimeoutSeconds`
- `PageSize`
- `TokenRefreshSkewMinutes`
- `AllowedStatuses`

As opcoes sao validadas no startup via Options Pattern. A validacao exige URL absoluta, `PartnerId`, `PartnerKey`, janela, timeout, pagina e status somente quando `Shopee:Enabled = true`.

### Persistencia de lojas e tokens

Foi criada a entidade `ShopeeShopEntity` e a tabela `shopee_shops`, com migracao `20260428000000_AddShopeeShops`.
A tabela armazena:

- `shop_id`
- `access_token`
- `refresh_token`
- `access_token_expires_at`
- `authorization_status`
- `created_at`
- `updated_at`

Os tokens sao protegidos pelo ASP.NET Core Data Protection no `ShopeeShopTokenRepository`.
O repositorio salva tokens protegidos e devolve tokens descriptografados somente para os servicos de infraestrutura da Shopee.

Status suportados:

- `Active`
- `ReauthorizationRequired`

### Assinatura Shopee

Foi criado `ShopeeSigner`, responsavel apenas pela assinatura HMAC-SHA256.
Ele monta a base de assinatura com:

- `partner_id`
- path da API
- `timestamp`
- `access_token`, quando aplicavel
- `shop_id`, quando aplicavel

O resultado e hexadecimal em lowercase. A logica de assinatura nao contem regra de negocio.

### Cliente HTTP

Foi criado `ShopeeClient` com `IHttpClientFactory`, `System.Text.Json`, timeout configuravel e tratamento explicito de erros.
O cliente cobre:

- troca de `code + shop_id` por tokens
- renovacao de `access_token`
- `get_order_list`
- `get_order_detail`

Erros sao classificados como:

- autenticacao
- rate limit ou transiente
- resposta invalida
- desconhecido

Logs evitam expor tokens e registram apenas path, codigo de erro, mensagem e identificadores operacionais.

### Fluxo de tokens

Foi criado `ShopeeTokenService`.

O fluxo implementado e:

1. `AuthorizeAsync` troca `code + shop_id` por tokens e persiste a loja como `Active`.
2. `EnsureValidAccessTokenAsync` verifica se o token vence dentro da margem `TokenRefreshSkewMinutes`.
3. Se estiver perto da expiracao, chama renovacao na Shopee.
4. Se a renovacao falhar por autenticacao, marca a loja como `ReauthorizationRequired`.

### Fonte de pedidos

Foi criado `ShopeeOrderSource`.

O fluxo de importacao e:

1. Carregar lojas Shopee com `AuthorizationStatus = Active`.
2. Renovar token antes das chamadas de pedido quando necessario.
3. Buscar pedidos por janela configurada e por status permitido.
4. Paginar com `cursor` enquanto `more = true`.
5. Buscar detalhes por `order_sn`.
6. Mapear detalhe Shopee para `RawOrder`.
7. Retornar a colecao para o `OrderImportPipeline`.

Falhas de detalhe de um pedido sao logadas e nao bloqueiam os demais pedidos da mesma pagina.
Falhas totais de uma loja sao agregadas; se nenhuma ordem valida for obtida e houver falhas, a fonte lança excecao para que o pipeline registre em `OrderImportResult.Failures`.

### Registro no DI

A infraestrutura registra os servicos Shopee:

- `IShopeeSigner`
- `IShopeeShopTokenRepository`
- `IShopeeTokenService`
- `IShopeeClient`

`ShopeeOrderSource` e registrado como `IOrderSource` somente quando `Shopee:Enabled = true`.
`InMemoryOrderSource` permanece registrado para desenvolvimento.

### Testes adicionados

Foi criado `tests/Craftsman.Tests/Integration/ShopeeIntegrationTests.cs`, cobrindo:

- mapeamento de detalhe Shopee para `RawOrder`, com item variado e item sem variacao
- renovacao de token antes da expiracao
- falha de refresh marcando reautorizacao
- `ShopeeOrderSource` com `HttpMessageHandler` fake cobrindo paginacao, detalhe por `order_sn` e erro parcial
- pipeline registrando falha da fonte Shopee sem bloquear outra fonte
- deduplicacao por `Source = Shopee` e `ExternalOrderId = order_sn`
- persistencia EF InMemory de loja Shopee com tokens protegidos

Tambem foram ajustados testes existentes em `ManualOperationsTests` para passar `NullLogger<OrderProductionPlanningService>.Instance` ao construtor atual de `OrderProductionPlanningService`.
